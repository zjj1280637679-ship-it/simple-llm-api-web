# 极简 LLM

自带 API Key 的极简 AI 网页 **v0.9.0**：对话、生成图片，以及自建视频 API。沿用同一套极简导航和输入框。

**[打开在线网页](https://zjj1280637679-ship-it.github.io/simple-llm-api-web/)**

![极简 LLM：历史卡冻结，末项卡可操作](knowledge/media/workbench.jpg)

## 三步开始

1. 打开在线网页。想在本机运行：下载仓库，在仓库文件夹的命令行运行 `python3 -m http.server 8000`，浏览器打开 `http://localhost:8000`。
2. 选择「对话」或「图片」，点 **＋ → API 设置**，填写服务地址、API Key 和模型。
3. 输入内容并发送；图片调用在确认卡确认后执行。密钥仅留在本页内存，模型费用由所选供应商收取。

## H3 队列控制台 · /api/v1/tasks

**[打开独立 H3 队列控制台](https://zjj1280637679-ship-it.github.io/simple-llm-api-web/h3-queue/)**：兼容 `/api/v1/tasks` 和 `X-API-Key`，可上传参考素材、单条/批量提交、监控进度、预览下载 MP4，以及暂停/恢复队列、置顶、取消、重试和删除任务。服务地址与密钥在网页中填写，密钥只驻留当前页面内存；本机仅存连接地址和部分任务 ID。需要后端对 GitHub Pages 来源开放 CORS。

此控制台**不替代**下方原有 `/v1/jobs`、Bearer/BF16 视频工作台，两种接口分别维护；详情见 [队列操作说明](docs/H3_QUEUE.md)。

**[MiniMax H3 中转站专用页面](https://zjj1280637679-ship-it.github.io/simple-llm-api-web/h3-relay/)**：与 H3 队列页面使用同一份 `/api/v1/*` 客户端、相同表单和操作，但独立保存中转站 URL 与任务 ID；API Key 均只保留在各页面内存中。中转站地址需在页面填写，不预设任何公网地址。

## 自建视频 API

选择「视频」，在「视频 API」中填入笔记本给出的公网 URL 和密钥，连接后添加参考图片、视频或音频，再输入描述并生成。至少需要一张图片或一段视频；纯文本、纯音频暂不支持。

高级设置可分别选择原生 BF16 注意力后端、已预加载的加速 LoRA 和步数。Turbo 需要显式设为 5 步（4 次模型评估），任务卡区分请求配置与实际应用回执。

模型尚未就绪时可先排队。任务卡显示排队原因与实际阶段，可取消指定任务；完成后可预览和下载 MP4。刷新后保留任务 ID，重新填写密钥即可查询原任务。密钥与参考文件不存入本机历史。

视频接口采用 MiniMax-H3 ref2va 自建服务契约，并非 OpenAI 视频接口。服务需允许网页来源的 CORS。[视频使用说明](docs/VIDEO_API.md) · [v0.9.0 更新与验证](docs/releases/v0.9.0.md)

## 千问官方文本 API 模板

在「对话 → API 设置 → 服务商」中选择「千问 · 百炼官方（北京）」或「千问 · 百炼官方（新加坡）」，输入对应地域的百炼按量计费 API Key 与模型 ID（例如 `qwen3.8-flash`），即可通过 OpenAI 兼容 `/chat/completions` 进行文本对话。地域与计费方案的密钥不可混用；网页不保存密钥。详见 [供应商预设说明](docs/provider-presets.md)。


## 文本模型联网搜索 · DeepSeek 官方默认

在「对话 → ＋ → 模型设置 → 更多参数 → 联网搜索」中启用「DeepSeek 官方 · 模型自主搜索」。

- 搜索服务固定为 DeepSeek 官方 `POST https://api.deepseek.com/v1/tools/search`。当前兼容支持函数工具的 Gemini、OpenAI 兼容与 Ark 文本模型；Anthropic 格式的工具调用尚未适配。
- 当主文本模型是**官方 DeepSeek**，可复用主 API Key；若主模型是千问、GPT、Gemini 或其他供应商，须在这里另填 DeepSeek 搜索 Key。搜索 Key 不会发送到主模型供应商。
- **默认搜索来源 DeepSeek，但开关默认关闭**，以免产生意外费用。启用后由模型判断是否需要搜索，而不是每次消息都强制搜索。本轮搜索无自动重试，和图片工具合计最多 4 次调用，单次最多返回 5 条结果。
- 搜索 Key 仅驻留标签页内存，不写入聊天历史、模型卡快照、浏览器存档或 GitHub。模型选择的搜索词会发给 DeepSeek；成功搜索请求可能单独计费。结果作为不可信引用数据交给主模型。
- 前端不能控制第三方服务的 CORS。此次只有模拟 HTTP 测试，没有真实 DeepSeek Key、额度、搜索或模型联网验收。

官方文档：https://api-docs.deepseek.com/guides/search/ （2026-11-16 核对）。

## 文本流式兼容 / 不完整回复

如果文本回复报「流式回复缺少完整结束证据；部分内容未加入对话上下文」，新版已能识别 OpenAI 兼容与方舟端点**完整结束标记 + SSE 自然关闭**的情况，不再单纯因为缺少 `[DONE]` 丢弃已完整生成的内容。真正的网络中断、缺失完成标记、`length` 仍不会伪装成成功。

对于经常出现 SSE 格式不兼容的中转站，可在「对话 → 模型设置 → 更多参数 → 响应方式 / 流式兼容」改为「完整 JSON · 稳定兼容（非流式）」。该模式不会实时逐字显示，也不会在失败后自动重发请求；默认仍为实时流式 SSE。[详细技术说明](docs/STREAMING.md)。
