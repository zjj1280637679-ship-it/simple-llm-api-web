# 设置层级与历史会话 · 开发试用版 0.5.0

2026-10-30。本阶段优先降低基础使用的注意力成本，接受精细配置多走几步。层级依据当前任务与控制需求；不把用户永久分成初级/高级，也不据此禁止边缘用途。

## 页面路径

- 输入区 `＋ → 设置`：服务商、密钥、模型；精细入口只有“模型设置”和“连接细节”。
- `设置 → 模型设置`：输出限制、采样参数、更多参数。更多参数继续分为思考模板和输入模态。图片场景保留输入区的规格入口。
- `设置 → 连接细节`：地址与协议。改变目标后按原有规则清除内存密钥，返回设置填写；不会因改名扩大凭据发送范围。
- `历史`：新建、查找、继续会话；每项的更多菜单提供重命名、单会话导出和删除。
- `历史 → 更多工具`：导入与导出、通讯记录、本地存储。通讯记录不等同于会话内容，仍仅在内存自动收集。

“模型设置”“连接细节”“返回设置”都经统一 dispatcher 生成新卡；原卡成为历史末项之前的记录。卡片数据没有新增存活/过期标记。参数折叠属于阅读展示，历史卡可展开阅读但字段与动作禁用。

本次按用户确定的“历史页”布局落地；左侧栏和独立浏览器窗口尚未实现。新建会话发生在当前网页。页面工具的内部路由 ID `logs` 保持兼容，用户标签为“历史”。

## 独立课题与关系

| 模块 | 责任 | 不拥有的状态 |
| --- | --- | --- |
| conversation-book | 会话身份、目录、选择、标题、归属 | 请求、DOM、存储事务 |
| conversation-archive | 集合编解码、旧档迁移、即时草稿归属 | 活跃请求与密钥 |
| settings-navigation | 3 类设置卡的 4 条跳转关系 | 渲染、字段效果、卡片活跃性 |
| settings-markup | 设置卡的层级展示 | 导航和外部效果 |
| history-markup | 历史目录与工具入口展示 | 删除、下载和存档写入 |
| workbench | 组合上述模块与原 dispatcher、保存、请求宿主 | 不再内联设置卡视图 |

每个新模块在 catalog 中有独立模块/宿主版本和时间。宿主直接导入生产实现；契约中的 F/C/H/Q 仍为 UNKNOWN，不把测试通过写成完整形式证明。

## 保存与效果归属

一条会话拥有独立的文本和图片工作区、草稿、附件、原生协议上下文和卡片历史。Agent 图片结果仍交付到发起它的工作区。切换时先提交当前集合；晚到文本和图片保持原工作区对象归属。页面工具的确认快照加入会话 ID，防止相同提示词和配置在另一个会话重用确认。

新会话继承当前连接与参数；密钥只在同一个页面的内存中继承，刷新与导出仍不保存。所有会话共用同一份有版本比较的 IndexedDB 记录；多窗口并发编辑仍会提示冲突，不支持跨窗口自动合并。

集合格式 `collectionSchema: 1`，内部工作区快照沿用 `schema: 2`。旧 schema 1/2 自动迁移成一个会话，不猜测旧记录的时间（显示“旧存档”）。新数据仅被本版读取；回退旧程序前应导出备份。

集合上限 48 MiB、目录预算 200 个会话。达到预算时提示导出/整理，不自动丢弃内容。128 KiB 同步草稿保护只覆盖带会话 ID 的当前工作区；完整历史和附件依赖完整集合提交。切换不会把前一会话的清空标记应用到后一会话。单会话导出为只含该会话的集合；导入明确替换当前全部会话，操作前确认。删除当前版本是确认后的删除，尚无回收站。
