# API 设置按请求动作应用

2026-10-29T15:09Z。本次遵从用户要求移除“应用设置/清除密钥”按钮；普通发送与拉取模型使用当前填写配置，不在填写时发请求。

- 正常发送/拉取时验证当前HTTPS目标，将规范目标放入本次调用配置；没有目标确认模态。图片生成与已连接工具发送的原有费用/调用确认不变。
- API Key直接映射当前工作台内存。重新打开API卡保留当前值，不用伪造掩码占位；用户删空时input即时清除配置key和旧应用标记，无需blur。历史卡不保留密钥且不能改当前配置。
- 更改地址/协议继续清除旧key和应用标记。发送前同步当前可编辑API卡，兼容未派发input的自动填充；如果地址无事件变更而key仍是旧值，不带旧key跨目标请求。当前图片配置可在聊天发送时构建已校验工具配置快照，不必先付费生成一张；实际工具调用仍单独确认。
- 秘密仍不进入仓库/导出/通讯日志；替换旧key前登记日志脱敏规则以保护已产生记录，不将其用作可调用配置。

[MDN input事件](https://developer.mozilla.org/en-US/docs/Web/API/Element/input_event)区分用户编辑事件和JS赋值；[WAI Change on Request](https://www.w3.org/WAI/WCAG22/Understanding/change-on-request.html)支持让用户请求动作触发变化。这里网络动作是发送/拉取，不是填写密钥。

离线测试覆盖重开保留、清空即时生效、旧卡隔离、目标切换清空、事件缺失同步、发送与模型列表、图片工具配置。tests/browser/attachments.html以dummy key和全替代fetch支持模拟发送/取模型，无实际供应商请求。

自动填充还纳入页面工具授权快照：确认文案生成前先同步当前DOM字段；确认后实际执行前再同步并比对快照，若期间目标/密钥/模型被改则拒绝该次执行，避免确认旧配置却发送新配置。离线回归覆盖确认期间无input事件的字段改动以及同改URL/新key连续发送。
