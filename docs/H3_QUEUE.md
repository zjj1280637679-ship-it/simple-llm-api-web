# MiniMax H3 队列控制台（/api/v1）

独立网页：[打开 H3 队列控制台](../h3-queue/index.html)；另有[MiniMax H3 中转站入口](../h3-relay/index.html)。两页共享相同的 `/api/v1/*` 实现与界面控件，分别将 URL 与任务 ID 存入不同的浏览器记录键，密钥不持久化；中转站公网地址由使用者自行填写。现有“视频”页面仍使用 `/v1/jobs`，本页使用 `/api/v1/tasks`；两种协议的鉴权、上传、任务 ID 和状态字段互不兼容，禁止互相推断。

## 三步使用

1. 启动自己的 H3 服务，提供公网 HTTPS URL，打开网页并在“连接视频服务”填入**服务基础 URL** 和 API Key。URL 可以带 `/api/v1` 后缀，前端会标准化；不要把 Key 追加在 URL 查询参数中。
2. 添加图片/视频/音频参考：本地文件先用 `POST /api/v1/upload` 上传再引用服务返回的文件名，也可填入 http(s) 参考 URL；图片还支持 `data:image/...;base64`。参考标记按类型独立排序：`<Picture 1>…<Picture 9>`、`<Video 1>…<Video 3>`、`<Audio 1>…`。
3. 填写提示词、画幅、时长、Turbo、优先级和种子，提交单条或批量任务。任务卡可以查询进度、置顶、取消、重试、删除、预览和下载。队列面板提供暂停、恢复和清理终态历史。浏览器离开不主动取消已提交任务。

## 连接、鉴权、隐私与限制

- 所有 /api/v1 请求使用 `X-API-Key` 请求头；浏览器不把密钥放入视频 URL、仓库代码、日志、localStorage 或查询参数，刷新后需重新输入。当前本机只存储 URL 和最近的任务 ID。共享设备用完后应关闭标签页。
- GitHub Pages 来源 `https://zjj1280637679-ship-it.github.io` 的服务端必须正确处理 `OPTIONS` 预检，并允许 `X-API-Key`、`Content-Type` 与相应方法。前端无法代替服务器开放 CORS。
- 下载使用带鉴权头的 `GET /api/v1/tasks/{id}/video`，再用当前浏览器生成的临时 blob URL 播放/保存。单文件内存下载限制 256 MiB；更大的文件需在服务端提供授权下载机制。
- POST 回执超时或错误时不自动重提，原操作可能已经被服务接收；刷新列表核对后再决定是否重新操作。批量任务数量由页面临时限制为 1–20，不代表服务的全局配额。
- 当前页面与 API 传输自动化只完成离线单元测试和模拟浏览器验收；不宣称公网 CORS、真实 GPU 视频、计费或云资源释放已经测试。

如 API Key 曾粘贴进聊天或泄露在公开位置，请在服务器上轮换后再上线。
