# Markdown 解析渲染模块说明与材料

本文件记录 `src/markdown.js` 的功能范围、语法子集、安全规则、边界行为与测试验证数据。

## 1. 功能说明

`src/markdown.js` 导出具名函数 `renderMarkdown(input)`。
- 模块采用原生 ES modules 规范。
- 零 npm 依赖，无外部库调用。
- 不依赖 DOM API，纯字符串输入输出，可在 Node.js 及浏览器环境中运行。
- 输入非法类型（非 string）抛出 `TypeError`；输入空字符串返回空字符串 `''`。

## 2. 语法子集

### 2.1 块级子集

| 语法结构 | 标记形式 | 对应 HTML 输出 | 说明 |
| --- | --- | --- | --- |
| ATX 标题 | `# ` 至 `###### ` | `<h1>...</h1>` 至 `<h6>...</h6>` | `#` 后须有空格；行尾以空格分隔的 `#` 序列去除并 trim（`# Title#` 的尾 `#` 保留，符合 CommonMark 闭合序列规则） |
| 段落 | 空行分隔 | `<p>...</p>` | 连续非空行以空格连接为单一段落（单行换行不生成 `<br>`） |
| 无序列表 | `- `、`* `、`+ ` 开头 | `<ul>\n<li>...</li>\n</ul>` | 连续同类列表项合并为一个 `<ul>`；`li` 各占一行 |
| 有序列表 | 数字 + `. ` 开头 | `<ol>\n<li>...</li>\n</ol>` | 连续有序项合并为一个 `<ol>`；与无序列表相邻则各自独立成表 |
| 围栏代码块 | ` ``` ` | `<pre><code>...</code></pre>` | 语言标记忽略；块内内容逐字转义，不做行内解析；未闭合直至文末 |
| GFM 表格 | `\| 表头 \|` + `\| 分隔行 \|` | `<table>\n<thead>...</thead>\n<tbody>...</tbody>\n</table>` | 第二行为分隔行（每格仅含冒号、连字符、空格且至少含一个连字符）；忽略对齐属性；行列数以表头为准 |
| 水平线 | 单独一行的 `---`、`***`、`___` | `<hr>` | 前后可有空格；第二行位置的连字符作为表格分隔行，其余单独成行为水平线 |

> 其余未纳入子集的块结构（引用 `>`、4空格缩进代码块、Setext 标题等）均按普通段落文本处理。

### 2.2 行内子集

| 语法结构 | 标记形式 | 对应 HTML 输出 | 解析顺序与规则 |
| --- | --- | --- | --- |
| 行内代码 | `` `code` `` | `<code>...</code>` | 第一优先级抽取占位，内部加粗/链接不解析；未闭合反引号保留为转义文本；代码内容仅转义 |
| 超链接 | `[text](href)` | `<a href="...">...</a>` | 第二优先级解析；文本内容支持强调嵌套；href 需通过协议安全验证 |
| 加粗 | `**text**` | `<strong>...</strong>` | 第三优先级解析；支持与斜体相互嵌套；未闭合标记原样保留为转义文本 |
| 斜体 | `*text*` | `<em>...</em>` | 第四优先级解析；未闭合标记原样保留为转义文本 |

## 3. 安全规则

1. **原始 HTML 全量转义**：
   模块内置独立转义函数，映射关系与 `src/view-markup.js` 的 `esc` 保持一致：
   - `&` -> `&amp;`
   - `<` -> `&lt;`
   - `>` -> `&gt;`
   - `"` -> `&quot;`
   - `'` -> `&#39;`
2. **超链接协议白名单**：
   - 链接 href 经过 trim 之后，仅允许大小写不敏感的 `http://` 与 `https://` 协议生成 `<a href="...">` 标签。
   - 任何 `javascript:`、`data:`、`vbscript:`、相对路径、页面锚点（`#`）、包含空格或引号（单引号/双引号/实体转义引号）的 href，一律降级为纯转义文本，不生成 `<a>` 标签。
3. **标签与属性白名单**：
   - 生成的 HTML 标签集合限定为：`p`、`h1`、`h2`、`h3`、`h4`、`h5`、`h6`、`ul`、`ol`、`li`、`pre`、`code`、`strong`、`em`、`a`、`table`、`thead`、`tbody`、`tr`、`th`、`td`、`hr`。
   - 除 `<a>` 标签的 `href` 属性外，所有其他标签均不携带任何 HTML 属性，禁止任何 `on*=` 事件处理器属性。

## 4. 边界与异常处理

1. **输入合法性与换行归一化**：
   - `typeof input !== 'string'` 时抛出 `TypeError`。
   - `input === ''` 时直接返回 `''`。
   - 统一将 CRLF（`\r\n`）与单独 CR（`\r`）归一化为 LF（`\n`）。
2. **列表扁平化与缩进归并**：
   - 缩进 2 空格或制表符以上的类列表行不创建嵌套列表，作为后续文本以空格连接拼入上一列表项。
   - 若当前无上一列表项，缩进行的类列表行退化为普通段落文本。
   - 连续同类列表（ul 或 ol）合并为一个列表块；不同类列表项相邻断开各自成表。
3. **表格异常容错**：
   - 若第二行分隔行校验失败（如包含非冒号/连字符字符、或不含连字符），放弃表格解析，整体按普通段落文本处理。
   - 表格行列数以表头列数为准：多余的单元格直接丢弃，缺失的单元格自动补空 `<td></td>`。
4. **未闭合结构保真**：
   - 未闭合的代码围栏（```）自起始行起逐字转义并包覆为 `<pre><code>...</code></pre>` 直至文末。
   - 未闭合的行内反引号、加粗（`**`）、斜体（`*`）标记保留为转义文本，不破坏周围文本布局。
5. **链接与占位符的已知边界**：
   - href 含未转义 `)` 时，链接在第一个 `)` 处截断（链接正则以 `)` 为 href 终结符），属本子集边界，不属安全缺陷（截断后的剩余文本仍转义）。
   - 强调解析不改写已生成的锚点：链接生成后整段 `<a>` 先抽为占位、强调跑完再还原，故 href 含 `*` 时原样保留，强调包裹链接的行为亦不变（见回归测试）。
   - 输入原文若恰好含与内部占位同形的 NUL 序列（如字面 `\x00CODE_0\x00`），该序列可能被占位还原逻辑替换，属极端输入边界；常规文本与代码内容不受影响。
