## 条件与版本

使用 v0.9.0 极简网页的本机静态服务，经临时 Cloudflare 公网地址连接带 Bearer 鉴权的 MiniMax-H3 ref2va API。提交、参考上传、取消、查询、预览和下载均经过实际网页；另有只读客户端核对相同公网 API 回执。

GPU 为 NVIDIA A100-SXM4-80GB。主干与 LoRA 保持原生 BF16，模型官方指定的 FP32 例外层保留，不启用量化。注意力选择作用于 `transformer_ref`。首轮服务实例为 `558799045c724b3b8bb3c4aa4ba24d7f`；故障恢复后模型子实例为 `4dd0a03428814323a8aa7f97f2ac9f12`。最终冷启动服务实例为 `0480a438ebc2486e8faa09a4671264ce`，模型子实例为 `5c6ffeac7054458a9f1f2075437805fd`。

网页源代码最终本地验证为 534 项测试：533 通过、1 项既有可选 MCP SDK 跳过、0 失败；26 项视频传输测试、47 项视频工作区测试，38 个宿主、6 个有限模型及 54 文件构建通过。首轮浏览器观察期间修复了状态文案和取消提示；最终源码冻结后重新加载新版网页，冷启动实例的上传、模型未就绪排队、指定取消、原任务对账、生成、预览与下载再次通过。

## 实测发现与修复

1. **可选 torchao 阻断普通 BF16 LoRA。** Colab 预装 torchao 0.10.0，PEFT 0.21.2 在遍历 LoRA 分发器时拒绝该版本，导致初始 `964f…` 失败。修复在专用运行时移除不使用的旧 torchao，保留 PyTorch/torchvision/torchaudio 与 psutil 栈；新进程实际执行微型 BF16 Linear 的 PEFT 注入和开关检查。后续成功生成确认实际模型加载路径恢复。新安装流程增加同类早检，避免等完整模型下载后才暴露问题。
2. **API 任务回执的实例归属。** 修复公共任务回执的服务实例校验与补齐，使网页可以在不混淆 manager/API 实例和可替换模型子实例的条件下恢复原任务。能力实例必须与系统观察一致，缺失或不匹配时只阻止新上传，保留已验证归属的查询、取消和下载路径。
3. **状态文案时效。** 连接时读取的能力 ready 值不能持续充当当前模型状态。高级帮助改为说明配置与接纳规则，执行状态取自任务卡；running 但阶段缺失显示等待阶段确认，gpu_wait 显示等待 GPU 资源，encode_validate 显示编码校验。
4. **取消回执可读性。** 仅 `cancelled` 且错误码精确为 `result_not_committed` 时显示“任务已取消，未提交视频产物”；取消待确认和其他错误保持原语义。异常配置回执不会再使任务卡刷新崩溃，也不会覆盖原提交配置。

配套后端与笔记本的 CPU 回归记录为 659 通过、8 跳过、1 条既有 Starlette 弃用警告；该记录是已完成工具输出的末段摘录，未冒充完整 stdout 或新一轮执行。后续 API 生命周期边界单独 106 通过；宿主请求绑定及旧宿主竞态的针对性回归 53 通过，Node 交付检查 2 通过。这些是不同运行和范围，不能累加成一项总测试数。来源分别为 `work/backend-cpu-validation-20261115.txt`、`work/backend-api-lifecycle-regression-20261115.txt` 与 `work/backend-warm-delivery-regression-20261115.txt`。

本轮实测的首个 Turbo `pipeline` 为 583.434298 秒，后续关闭 Turbo 的狐狸任务为 201.432115 秒。最终新实例茶壶任务 `pipeline` 为 357.714909 秒，生成阶段 `metrics.wall_seconds` 为 359.442111 秒；该指标不包含此前模型下载等待。三次输入、参考类型、步数或冷热状态不同，不能计算插件或 LoRA 的加速倍数，不能用这些值判定某方案更快。
