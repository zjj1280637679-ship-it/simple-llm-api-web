# 2026-11-04 Gemini 适配

审查基线 `df4f04b1685d7de09572f904f4c6f32c5ff66d10`，项目 0.6.0。理想效果、条件、职责矩阵和反例见 [模型](../../design/GEMINI_ADAPTATION.md)，入口和官方来源见 [使用说明](../GEMINI_ADAPTATION.md)。

## 实际缺口

- Gemini 设置展示跨供应商思考模板，接口不兼容选项占据空间。
- 模型列表只保留名称与方法，thinking / topK / 输出上限信息丢失。
- 缺少 generateContent 的思考摘要、媒体精度、seed、stopSequences 与 Top K 控制。
- 保存偏好、当前可应用字段和历史解释没有 Gemini 能力层的统一依据。

## 实现

F-021 解释协议、具名模型资料与当前 Model 回执；F-022 投影实际请求；F-023 生成深层控制和快照摘要。三块均无密钥读取、网络或持久状态，分别有版本、时间戳和最简宿主。组合层绑定/撤销回执，动作沿用现有 dispatcher；历史末项仍是业务交互条件。

确定不支持时收缩 UI 并省略请求字段；unknown 保留深层手动入口。配置变更不自动发请求。具名规则只用于匹配官方地址的明确模型 ID；不按 key 前缀、别名或未来模型名猜能力。已拉取模型的负证据可收缩思考与 Top K；列表不提供 generateContent 的条目移入只读分组。

新增可选字段默认不发送；保留 false 和 0；thinkingConfig 摘要与预算/档位合并。采样被忽略时，旧值即使不合当前数值条件也不阻断发送，因为其不进入当前请求。未知模型可深层选择预算/等级格式，但仍要显式设置强度。格式变化及时更新底部默认状态。
