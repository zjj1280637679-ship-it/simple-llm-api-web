# 图片页 Gemini 适配审查

版本 0.7.0；基线 03c7cd681434739e6cc5f70a2fa41c98ee21abc2；2026-11-04。

问题：图片页只认识 Nano Banana 2.1，一个通用参数面板无法表达模型差异；模型设置没有可用的 Gemini 图片控制，固定“一张”又超出原接口保证。

结果：F-024 统一精确模型表、可用参数、工具 schema、有效偏好和请求序列化；F-020 投影图片控件与历史行。宿主保留跨模型偏好，当前参数独立持久化；历史卡在冻结时记录当时有效值，缺失旧值不猜测。图片生成确认展示有效返回模式/思考等级；对话中的图片工具复用图片页设置。

反例与处理：

- Gemini 2.5 固定 1K：界面没有 2K/4K；HTTP 不含 imageSize。
- Nano Banana 2.1 的 medium 切到 Flash：保留偏好并说明暂未应用；HTTP 没有 thinkingConfig。切回恢复 medium。
- 1:8 / 4K 切到窄模型：当前回落到 1:1 / 1K，偏好不覆盖；切回恢复。调整一个轴不重置另一轴。
- 未收录模型：可保留 ID，但不套邻近模型规则；模型列表优先已适配图片，其他方法只读。
- 当前模型变更或刷新：冻结历史不变化，专属参数和偏好可保存；真实密钥仍不落盘。
- 精确像素未登记：返回图片可解码和显示实际宽高，尺寸匹配保持 unknown，不借用 Nano Banana 2.1 像素表。

本地证据以 `development/evidence/review.json` 的输入/输出指纹和时间为准；合成 HTTP 走真实命令路由，UI 走生产 workbench；有限模型覆盖登记域组合与跨模型偏好往返。完整 F/C/H/Q、真实 Gemini 密钥、全部浏览器和画面语义效果未由这些测试证明。

官方资料有本轮阅读日期、链接及 Lite 比例冲突的明确取舍，见 [图片适配](../IMAGE_ADAPTATION.md)。浏览器发布验收另存知识附加记录，不把旧截图称为新版本结果。
