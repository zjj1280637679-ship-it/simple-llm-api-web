# 主线入口与实验连接

更新：2026-10-30（北京时间）；适用于 v0.4.0。**产品定位与验收成熟度是两个维度**：列为主线不表示所有场景均已验证，实验性也不表示没有能力。

| 路径 | 定位 | 已有证据 | 尚缺什么 |
| --- | --- | --- | --- |
| 普通网页：对话、图片、交互卡 | 当前主线 | 本地回归、发布与有限 UI 观察；历史 Ark 图片单次成功 | 四协议文本的当前版本实网流式验收；其他条件见验收表 |
| `cli/cli.mjs` 图片 CLI | 独立辅助入口，实网待验收 | 本地进程、共享 dispatcher、合成图片写盘 | 真实供应商请求和实际图片文件验收 |
| WebMCP / `src/session-webmcp.js` | **实验性** | 注册、部分页面往返、确认卡取消观察 | 长等待后返回调用方、真实调用和取消的完整链路 |
| `cli/web-cli.mjs` | **实验性** | 命令校验、合成 stdio 路由 | 真实 CLI → 浏览器宿主 → 选中页面 → 返回 CLI |
| `cli/cli-mcp-transport.mjs` | **实验性** | 合成 peer；可选真实 SDK 对合成 peer 测试 | 受支持宿主/浏览器版本组合与实际连接、断连、取消 |

普通网页不依赖后三项；不需要为聊天安装 MCP SDK 或浏览器扩展。实验连接的安装与参数仍可在 [WEB_SESSION.md](../WEB_SESSION.md) 查阅，文档示例本身不构成兼容性承诺。

## 已知的实际观察

[v0.4.0 发布记录](../knowledge/snapshots/v0.4.0-6a2e6c012766/deployment.md)记录了工具发现、草稿设置后出现确认卡、通过 UI 取消，以及旧卡冻结。调用方等待异步工具回复时出现 `Runtime.evaluate timed out`；恢复控制会话后才完成 UI 取消。因此“页面动作生效”和“外部工具收到完整结果”必须分开。

云浏览器的页面工具桥接也不等于项目的 `web-cli.mjs → Playwright MCP extension` 路径。一次桥接失败不能证明所有宿主不可用；一次 UI 成功也不能证明终端宿主闭环已通过。

## 从实验性转为已验收连接的条件

对**一个明确版本组合**记录 CLI/SDK/宿主/浏览器版本、项目提交、目标页面与授权方式，完成：

1. 状态 → 改草稿 → 页面可见 → 再读状态 → CLI 正常退出，且均为同一个页面。
2. 拒绝确认后供应商请求数为零，CLI 收到未发送结果。
3. 确认后一次真实请求，页面与 CLI 对完成/失败的结果一致；记录请求身份和时间。
4. 等待确认、请求中、断开连接三种条件分别检查取消与资源释放；其他条件未验证时保留范围。

单个宿主通过后记录支持组合，不把结果扩展到全部浏览器。验收状态按 [实网验收表](LIVE_ACCEPTANCE.md)更新，不以“experimental”代替具体证据。
