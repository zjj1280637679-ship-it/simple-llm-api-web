# 交互卡协议 v1 · 项目 v0.4.0

本轮目标是极简视觉与使用体验，并把卡片作为历史中的一等对象。参数表、设置、图表、确认和日志可以共享承载方式；是否值得做成卡片仍按具体任务判断。当前实现不宣称所有界面都已迁移。

## 位置即活跃性

设一个工作区的可见历史为 H，卡片身份为 c：

`live(H,c) ⇔ H 非空 ∧ H[-1].type = card ∧ H[-1].id = c.id`

每个工作区至多一张活卡。卡片后面任何历史项——用户输入、回复、状态、错误或另一张卡——都使它成为历史记录。不存 active/pending/expired，不搜索“最后一张卡”。草稿尚未提交时不是历史项，切换页面不改变所在工作区的历史位置。

活跃性是一种位置关系；动作还有自身条件。例如忙碌时暂停修改调用配置，确认卡仍允许回应；已恢复的确认记录没有等待中的调用可供继续。这些条件不另建卡片生命周期状态。

## 数据协议

```json
{"id":17,"type":"card","kind":"chart","version":1,"values":{"title":"末次请求用量","rows":[{"label":"输入","value":null}],"note":"未知不记作零。"}}
```

| 字段 | 意义 |
| --- | --- |
| id | 工作区历史中的唯一身份；导入还校验全局唯一性 |
| type | 历史项类别，卡片固定为 card |
| kind / version | 类型及其数据协议版本，不等于模块版本或应用版本 |
| values | 参数、展示快照与业务数据；没有卡片活跃标记或可执行代码 |
| 动作 | 由当前程序中登记的类型定义提供，不相信历史数据自带的 handlers/command 字段 |

API 卡的密钥绑定工作区内存，不进入 values。菜单、模型列表与显示密钥等 UI 临时字段不持久化。新增历史前统一捕获末项设置快照；冻结后不会随当前设置变化。图表与日志也是快照，需要在活卡上主动更新。

## 从事件到效果

`卡片事件 → dispatchCommand(card.action) → 类型登记/参数校验 → 当前位置与条件检查 → handler → 效果`

字段编辑、按钮和设置卡键盘打开菜单共用入口。异步模型列表带有 commit 回调，写回前复查卡片身份和位置；晚到结果不会改写已成为历史的卡。

默认 image.generate 上下文没有 cardRuntime；模型工具参数也不能提供它。UI 卡片的动作并不会自动变成模型可调用权限。未来 AI 输出结构化卡片时仍需显式的类型映射与动作授权宿主，不执行任意模型 HTML 或函数。

## 已登记类型

| kind | 数据与动作 |
| --- | --- |
| api | 地址/模型快照、内存密钥绑定、供应商与模型列表动作 |
| model | 参数和输入模态、思考模板选择 |
| chart | 末次请求输入/输出/总量；未知为 null；主动更新 |
| logs | 当前脱敏内存日志的拷贝；主动更新；进入历史后随本机存档保存 |
| confirmation | 目标/提示词等确认说明，确认或取消；当前用于图片生成、Agent 调图和页面工具发送 |

确认卡不存“等待/过期”状态。card-confirmations 只拥有每个工作区至多一个 Promise 延续；回应消耗一次，追加其他历史、取消或 dispose 释放等待。响应产生一条历史回执，原卡自然冻结。刷新不恢复 Promise、不自动发送请求；旧确认数据不会授予新调用权限。

备份导入当前仍用本机保存面板及独立确认；普通文本/图片结果仍有自身展示器。它们可继续按明确需求迁移，不能把这次抽象误称为全站完成卡片化。

## 增加一种卡片

1. 在 `src/card-types.js` 定义版本、数据捕获/校验和参数范围；外部状态要明确是否属于快照。
2. 提供转义后的展示函数，使用 `cardShell`；在 `src/workbench-cards.js` 的同一条类型定义中登记展示和动作。共用历史/导航/动作分发不新增 kind 分支。
3. 若动作等待外部结果，使用注册表提供的 commit/current 检查；外部效果已发生与允许写回历史是不同命题。
4. 给模块和宿主分别登记版本、时间、目标、反例与证据。覆盖追加非卡项、旧事件、异步晚到、恢复、跨工作区和资源释放。

运行 `npm run models` 检查有限位置模型。该模型不证明任意 DOM、任意历史长度的抽象对应或外部网络效果；F/C/H/Q 仍分别验收。

## 兼容与保存

工作区存档 schema 升到 2；读取 schema 1 的 api/model 卡并补版本身份，旧文件不需要手工修改。未知 kind/version 以转义数据呈现并保留，当前程序不推测其动作。完整 JSON 复制仍有既定深度/节点和存档大小预算。

自动通讯日志继续仅在内存。用户主动插入日志卡时，日志副本成为历史内容，随历史保存/备份；卡内会说明这一点。凭据按现有规则脱敏，不保证识别从未登记的任意秘密。API Key、目标确认、Promise 和请求控制器不写入存档。

## 0.5.0 设置卡层级

API 卡的内部 kind 保留 `api`，用户标题改为“设置”；新增 `connection` 表示连接细节。`open-settings-card` 经类型登记与末项检查调用关系表，再由组合宿主追加卡片。返回同样生成新设置卡。见 [设置与历史](SETTINGS_HISTORY.md)。
