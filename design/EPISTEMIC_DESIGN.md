# 开发态的认识论设计 v0.3.0

2026-10-30（北京时间）。本规格将“代码可解释”落实为可分开检查的判断链：**输入/观察 → 局部解释 → 场景策略 → 执行效果 → 目标验收**。不同层可以独立变化；不以统一的 success、safe、valid 代替所有命题。

## 课题边界及当前实现

| 课题 | 负责模块 | 输入和输出的意义 | 不由本课题推出 |
| --- | --- | --- | --- |
| 目标是否合法且与本次确认一致 | api-target | 当前公共网页的 URL/凭据绑定策略 | 域名所有权、模型权限、所有其他宿主也必须使用此策略 |
| 传输看到什么 | request-transport | HTTP、SSE/JSON、取消、有限诊断及宿主来源声明 | 响应的业务正确性、错误的唯一根因 |
| 结束标记如何解释 | completion-evidence | 完整、明确未完整、拒绝、未知及具体类别 | 是否应该接纳、任务是否达成 |
| 当前入口如何接纳 | completion-policy | admitted + policyId + reason | 未接纳等于目标不可能实现，或接纳等于目标完成 |
| 图片已发生什么效果 | image-evidence | 解码/尺寸/工作区存入的独立字段 | 持久化事务、用户实际看见、满意度 |
| 页面发送返回意味着什么 | request-outcome | 控制流 returned、协议状态、交付、仍未知的效果 | 将旧 completed 字段扩张为全部成功 |
| 外部效果如何组合 | core / agent / workbench | 参数、工具流程、UI/保存及回调协调 | 单块通过自动保证组合通过 |

当前 21 个登记构件的契约同时给出课题、目标、状态预算/外部条件、反例、扩展点与证明义务。状态预算没有完成有限化的部分如实写明；没有把契约变长当成已形式验证。

## 注释表达理由与作用域

源文件首先回答“这个块独立解决什么问题”，再交代观察边界、状态所有者及扩展方式。关键分支解释依赖的事实/策略和代价；机械复述语句、无条件的“最佳实践”或缺依据的确定性词语不提供额外解释。

例如缺少结束字段时：证据层记为 unknown；JSON 兼容策略允许特定协议继续；SSE 策略要求终止证据。将兼容策略收紧，应修改策略及其反例，而不是把“缺字段”改写为“上游失败”。未来新增结束标记时，扩展解释表与来源范围，不让任意非空字符串自动升级为完整。

“必须/禁止”仍可表达有目标依据的必要条件。审查关注其前提、责任及复核触发，不能通过禁用某个词替代判断。

## 状态和副作用的控制

纯判断块不读取 DOM、时间、网络、存储或全局配置；输入和返回值体现其全部判断依据。资源块记录所有者、释放点与晚到结果的处理。组合块只在明确的阶段调用这些关系，不用文件转移掩盖共享状态。

此次 core 保留协议/业务 facade，公共入口兼容重导出；URL 策略和实际传输拥有独立模块。request-lifecycle 只依赖共同错误类型，不再为了一个错误类引入整个 core。默认传输观察者与日志仍限定页面/进程作用域，多租户实例隔离没有因此自动完成。

扩展同一效果可增加不同实现/宿主，前提是说明输入输出观察语义、条件、预算与替代成本。对未注册的本机模型、批量授权、自动重试或新协议，当前限制表示当前宿主选择；新路线通过对应实验与验收建立，不由标签一票否决，也不因绕开判断而宣称等效。

## 形式验证的实际入口

`development/models/` 直接调用生产纯函数，穷举明确有限输入分类。它检验局部不变量，仍保留输入抽象与所有 JavaScript 行为之间的对应义务。有限模型通过、宿主通过、真实场景满足、成功路线距离和最低效果分别记账；当前全模块 F/C/H/Q 不自动从 UNKNOWN 晋级。

具体模型、公式、信任基与未证明部分见 [有限模型说明](../development/models/README.md)。真实模型调用不是本轮实验条件，外部资料也没有因代码重构被重新核验。

## 变更时的检查顺序

先写被修改的命题和适用场景，再定位观察者、解释规则、策略消费者及效果见证。只对发生变化的责任修改版本和判据；源文件或共享验证依赖改变时更新宿主身份。组合回归检查取消、旧状态、未知状态、无结果与部分成功，最后更新证据和知识快照。

结构检查只能检查记录存在和身份相符；可解释性、课题是否恰当、替代路线是否有效及证明是否充分仍需实质审查。本规格不额外制造审批或多人流程。
