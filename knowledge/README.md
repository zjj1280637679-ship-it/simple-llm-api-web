## 两种阅读深度

| 需要 | 建议顺序 |
| --- | --- |
| 快速定位 | 本页 → 快照导览前两节 → `route` 对应主题 |
| 深入修改 | 核对指纹 → 目标/场景/决策 → 模块契约及状态归属 → 相关流程 → 宿主/反例/消费者 → 验证记录与未完成义务 |
| 查询结论依据 | `search` 找节点 → `show` 看来源路径、固定 Git blob 和行锚点 → 在源提交中阅读原文 |
| 判断变更影响 | `impact` 查看字面导入反向闭包、关联模块/宿主/测试 → 补查注入、事件、共享状态及外部条件 |

```sh
node knowledge/check.mjs
node knowledge/query.mjs overview
node knowledge/query.mjs route storage
node knowledge/query.mjs search 原生
node knowledge/query.mjs show R-010
node knowledge/query.mjs show flow:image
node knowledge/query.mjs impact src/persistence.js
node knowledge/verify.mjs
```

工具使用 Node 内置模块，离线读文件，不启动网页或模型请求。知识文件不在生产构建白名单内。`check.mjs` 为 MATCH 返回 0、DRIFT 返回 1、结构无效返回 2；查询参数错误返回 2。

[verify.mjs](verify.mjs) 是知识工具自己的 1.0.0 最简验收宿主：在临时副本里刺激内容变化、文件缺失/新增、悬空关系、错误行锚点及路径越界，并运行主要查询。[本次验收记录](verification.json)保留工具/宿主版本、执行时间和输入指纹。这套工具现已进入 PR/main 的 CI；检查范围仍是结构、指纹与导航反例，不扩张为语义充分性证明。

## 这个快照保证什么

建立时，260 个本地项目文件逐字节与 GitHub 源树匹配；图中保留 Git blob SHA、SHA-256、原始证据时间、模块/宿主独立版本。结构检查涵盖节点/边身份、引用闭合、文件指纹和行锚点。

这些检查支持“摘要指向哪版内容”，不证明摘要语义完整、历史报告真实、外部服务当前可用或程序形式正确。静态导入关系使用有行锚点的字面提取；动态 import、注入、DOM 事件、网络和语义依赖没有被穷尽。状态字段描述命题类型，不是从低到高的统一可信度评分。

知识图发布提交相对其项目源提交仅修改根 `AGENTS.md` 与 `knowledge/`，所以快照所描述的项目版本与知识图发布提交分开。检查器排除这两个发布附加项，以及 `.git`、`dist`、`node_modules`；其他新增文件也会提示漂移。它不会联网核对远程 HEAD。使用前另确认当前工作分支，避免把未同步工作区当成最新主分支。

## 更新快照

1. 确定已经提交的项目基线，记录完整 commit/tree SHA；核对工作区内容，明确尚未提交的改动。应用版本、知识版本、模块版本、宿主版本各自保留。
2. 运行检查器定位变化。重读受影响目标、条件、源码、调用者、契约和证据；补充已知的注入/事件关系。新增文件不能只被静默忽略。
3. 建立新的 `snapshots/<应用版本>-<提交前缀>/`，按 schema 更新文件节点、语义节点、来源锚点、关系、主题路由及导览。现有生成方法为 Git 树清单 + 静态导入字面提取 + 人工语义梳理；本版不提供伪装成全自动理解的生成命令。
4. 保留旧快照。旧快照错误通过新的修订及勘误关系说明，避免把旧证据移花接木到新版本。原始实验时间不改成知识图生成时间；没有重新运行就不写“重新通过”。
5. 检查结构、文件身份、链接和关键查询；涉及程序行为时再运行对应宿主及回归。指针更新到新快照，并更新入口中的快捷链接。
6. 单纯换提交不自动产生新理论阶段。需求/条件方向漂移时，另行定义阶段范围、策略和指标，并重验开发参考与运行投影的对应关系。

图谱陈述发生变化时更新知识版本；图结构或查询接口不兼容时提升 schema 主版本。维护由本次变更负责人完成，不额外要求固定审批人数。
