# H-R-004：配置历史与固定运行快照的最简宿主

对应 R-004 `simulator.profile-history`。宿主版本、创建和更新时间以 [宿主目录](../catalog.json) 为准。

```sh
npm run modules:host -- R-004
# 或 node module-library/hosts/configuration-profile/run.mjs
```

需要 Node.js 20+、Web Request/Response API、临时目录读写及同一文件系统硬链接能力。默认 `synthetic`（配置文件操作为本机真实操作，响应来自受控 fixture）；不提供 live 模式，不读取密钥，不使用生产请求构造器或 Gemini/Ark 资源包。

## 提供的环境和验收目标

宿主自带一条 JSON 请求/响应脚本、一个最小可信协议适配器、资源修订描述和临时配置目录。`fixture.mjs` 是该宿主自己的输入，不是另一份引擎实现；它对每次 `getFixture` 调用返回独立深拷贝。全部输入文件由现有证据指纹覆盖。

1. 恢复预设产生第 1 个修订；load 新响应产生第 2 个修订；恢复第 1 个修订产生第 3 个修订，而非重写历史。
2. 逐个 parent 哈希相连，第 1 个文件字节不变，恢复后的配置哈希等于第 1 个配置。
3. 已启动的第 1 个快照在后续写入后保持固定；其 reset 是独立空会话。显式启动历史修订 2 返回新响应。
4. 三个运行实例各自完成脚本；输入 fixture 没有被改写；在 finally 中销毁实例并删除临时目录。

成功输出 JSON 包含修订和观察，失败退出码为 1。最简性依据：无 UI、服务、供应商适配器和持久业务数据，只保留验证历史链和运行快照关系所需的协议输入、文件系统和会话。此为工程边界，不宣称数学意义上的全局最小。

## 结论边界

验证的是本地 append / restore / replay 关系，不是外部模型、账户、概率分布质量、崩溃恢复、恶意并发文件系统或配置加密。临时目录会被清理，不提供用户配置导出。宿主通过不自动提升 F/C/H/Q。
