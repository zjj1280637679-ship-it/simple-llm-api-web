# H-R-001：image-command.dispatch 的最简宿主

对应模块：R-001@0.1.0。宿主版本、创建与更新时间以 [宿主目录](../catalog.json) 为准。

在仓库根目录运行：

```sh
npm run modules:host -- R-001
```

也可直接运行 `node module-library/hosts/image-command/run.mjs`，不依赖完整网页或测试套件。输出 JSON 包含模块与宿主修订、模式、验证时间、观察结果和限制；失败退出码为 1。

## 这个宿主提供什么

- 命令与独立 context
- 未确认/已确认两种条件
- 下游响应与结果文件

最简性依据：只提供命令、上下文和可观察下游，不需要 UI 或 Agent。 这是当前契约下的工程边界，不宣称全局最小。

## 环境与验收

- Node.js 20+ 与可写目录
- 真实模式需要 Ark 图片 API 条件

成功判据：

- 未确认时零传输
- 确认后命令到图片执行器的关系成立，结果可读回

默认模式为 `synthetic`。真实模式使用 `--live`，需要从环境提供 `ARK_API_KEY`；详细设置见 [总说明](../README.md)。本次只运行默认模式。

## 结论边界

- 默认下游响应受控，不能证明外部服务可用
- 不是操作系统 shell 或授权系统的完整验证

宿主通过只支持以上判据；不自动使 F/C/H/Q 通过。测试宿主、夹具、观测或判据改变后，需要更新宿主时间与必要版本并重新验证。
