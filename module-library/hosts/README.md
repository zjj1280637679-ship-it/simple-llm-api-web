# 最简测试宿主

每个构件除了代码入口，还绑定一个能承载其目标效果的最小环境。目标可以是直接输出，也可以是参数转换、关系路由、状态联系或组合效果。宿主提供必要条件、刺激、结果承接和验收判据。

## 宿主目录

| 模块 | 宿主 | 可观察效果 | 默认模式 |
| --- | --- | --- | --- |
| F-001 | [图片参数宿主](image-options/README.md) | 参数转换和无效选项拒绝 | local |
| F-002 | [文本宿主](text-generation/README.md) | 请求映射和文本返回 | synthetic |
| F-003 | [图片宿主](image-generation/README.md) | 图片字节提取、落盘和读回 | synthetic |
| R-001 | [命令关系宿主](image-command/README.md) | 未确认不调用、确认后执行及结果传回 | synthetic |
| R-002 | [状态关系宿主](page-session/README.md) | 命令改变最小状态，后续命令能观察该变化 | local |
| F-004 | [请求契约宿主](fixture-contract/README.md) | 非变异参数绑定、精确匹配与字段脱敏 | local |
| F-005 | [PNG 检查宿主](png-inspection/README.md) | 尺寸/解码字节及损坏/超界拒绝 | local |
| R-003 | [会话关系宿主](simulator-session/README.md) | 顺序接纳、独立交付、取消/处置及隔离 | synthetic |
| R-004 | [配置历史宿主](configuration-profile/README.md) | 追加修订、固定快照、历史 replay 及 reset | synthetic |
| C-001 | [组合宿主](agent-image-turn/README.md) | 工具请求、图片结果、上下文保存、后续对话 | synthetic |

`local` 表示本机实际执行目标功能；`synthetic` 表示执行真实模块，但外部服务由受控响应代替。四个联网构件另有 `live` 入口，但证据范围不同：F-002/F-003 调用独立 HTTP 探针，`adapterVerified:false`；R-001/C-001 仍调用生产适配器/组合。详见下方真实模式，不能把前者的传输成功计为后者的适配器验收。本文档修订只复验离线路径，没有运行 live 模式。

## 如何使用

位置：仓库根目录的命令行。需要 Node.js 20+；本轮使用 Node.js 24。

```sh
npm run modules:host -- F-001
npm run modules:host -- R-002
npm run modules:host -- F-003 --out /tmp/image-host-results
npm run modules:host -- C-001
npm run hosts:verify
```

每个宿主的 run.mjs 可直接运行。共享 support.mjs 仅提供输入、配置、夹具、文件承接和报告，功能仍由已登记的模块实现。

每次输出独立 JSON 结果，包含模块版本、宿主版本及时间、验证时间、模式、观察与限制。图片文件写入指定目录内的唯一子目录；未指定时写入系统临时目录。合成图片是可检查的 1x1 PNG，不能把请求尺寸当作夹具的实测尺寸。

## 真实模式

按当前目标选择入口，不因宿主登记了 live 就自动执行它：

- **F-002 / F-003：独立传输探针。** 使用 `--live --live-plan FILE`，必须提供实际获批且未过期的单次计划和环境变量 `ARK_API_KEY`。精确模型、输入、输出限制和预估费用写在计划中；官方普通 Ark 地址固定，不使用 `ARK_BASE_URL` 或环境模型覆盖。报告 `adapterVerified:false`、`requestMappingChecked:false`，不经过生产适配器或其日志，也不保存响应图片。计划格式、边界和调用方式见 [Live probe](../test-resources/ark-native/LIVE.md)。传输 PASS 不等于 F-002/F-003 适配器或网页真实验收。
- **R-001 / C-001：关系与组合真实路径。** 当前仍用 `--live --prompt TEXT` 和生产适配器；`ARK_API_KEY` 提供凭据，`ARK_BASE_URL`、`ARK_TEXT_MODEL`、`ARK_IMAGE_MODEL` 是可选配置。R-001 将该次执行映射为已确认 context，C-001 只批准第一次图片工具请求，但可能有多次文本请求。执行前应根据本次目标、目标地址、模型与费用范围判断是否已获授权；F-002/F-003 的一次探针批准不自动覆盖这些路径。

默认 local/synthetic 模式不读取真实凭据，且真实 fetch 被阻止。真实调用可能消耗额度；120 秒信号期限和不自动重试不代表服务端已经停止生成或计费。配置中的确认字段只是程序条件，不替代真实授权。

真实文本模型如果没有调用工具，C-001 报告该宿主目标未达成，而不是仅凭文本成功就判组合通过。真实模式当前只为 Ark 提供配置接线；其他协议需另补宿主场景，不能从现有结果推断可用。

## 身份、维护和证据

宿主是独立版本化的验证设施。登记包含 ID、version、createdAt、updatedAt、被测模块 ID/版本、效果目标、必要条件、提供的环境、验收判据、模式、限制和最简性依据。

- 模块与宿主的版本独立，目录固定具体绑定。
- 宿主实现、夹具、模式或验收语义变化时，更新宿主版本和时间；纯登记修正可以只更新时间。
- 宿主也保留创建时间、版本不倒退；依据已有验证记录检查。
- 证据同时绑定模块修订、宿主修订和源码指纹。旧宿主的 PASS 不会自动传给新宿主。
- 每个默认宿主以独立 Node 进程纳入本地验证。真实模式报告需另存并评审其条件范围；不会被本地 record 冒充。
- 宿主不能偷偷完成被测模块的工作；受控服务、状态处理器和结果接收器均写明责任。
- 增加宿主不增加生成算法的替代途径数量，也不替代形式证明和组合真实验收。

隔离或归档构件仍可借助宿主做诊断，报告会显示其维护状态；测试通过不自动解除隔离。单个宿主只校验自身与被测模块的绑定，不要求无关模块或整套网页可运行。“独立”指所声明依赖闭包内可单独启动，不表示所有宿主都能只复制 run.mjs 跨仓库运行。消费者可以建立自己的最简宿主，按 [借用说明](../BORROWING.md) 记录独立结果。

完整网页不是每个模块的必要宿主。R-002 使用内存状态即可检验关系效果，但它不证明网页 DOM 或 MCP 宿主已跑通。图片宿主目前验证字节传输和文件承接，不负责完整解码、实测尺寸或内容质量。


共享模拟模块的四个宿主不导入生产 provider，不经 Gemini/Ark 宿主代测。F-004/F-005 只需内存输入；R-003 注入自己的脚本/手动 scheduler；R-004 注入自己的小型 adapter/fixture，并在 finally 删除临时配置目录。后两者的 SIMULATED 仅表明受控请求响应脚本，实际本地状态和文件关系确实执行。宿主 fixture/helper 同样由既有证据指纹绑定，不另建资源 registry。
