# 开发态模块图书馆

版本 0.4.0。当前索引见 [catalog.json](catalog.json)，每个条目指向唯一生产实现、契约和带独立版本/时间戳的最简宿主。不复制另一份“库专用实现”；宿主直接调用真实导出入口。

分类按效果责任：function 为局部计算/解码适配，relation 为状态归属、依赖和交付关系，composition 为完整启动组合。目录位置不决定类别。当前纳入 26 个已跑通本地宿主的条目，其余既有代码仍通过全仓回归覆盖，不能将本索引误读为全仓库已完成原子分解。

`npm run hosts` 可运行全部已登记宿主。报告包括模块与宿主版本、时间、运行模式、观察结果以及字面导入闭包的指纹。模拟时钟、存储或解码器会在范围中说明；局部 PASS 不自动变成真实 API、所有浏览器、完整形式证明或 Hamming 路线独立性的 PASS。

维护规则：

1. 先修改目标/输入输出/条件/状态责任，再修改代码。仅挪文件不算解耦。
2. 已发布的模块效果或接口变化更新模块版本；宿主/共享验证依赖改变更新宿主版本和更新时间。绑定保留具体版本，不用“最新版”替代身份。
3. 新功能、关系或组合必须有能触发并观察其目标效果的最简宿主，包括反例与失败出口。缺条件时给出缺失项和替代实验，不伪造通过。
4. 变更后重新运行受影响宿主与组合回归，再生成证据。指纹变化或输入集改变使旧证据过期；历史观察保留在对应 Git 提交。
5. F/C/H/Q 分开管理。可限定借用有本机证据的候选，但借用范围和剩余义务必须随契约一起提供。
6. 宿主不得默默读取真实密钥或发起付费调用；真实条件实验另行明确目标、资源和预算。这是当前实验授权范围，并不排除经授权的真实验证。
7. 原候选 PR #1/#2/#4 的提交身份保留在 catalog。当前选择沿用它们的分类、宿主和证据设计；其旧实现及测试结果没有直接覆盖当前消费者。结构化输出为独立功能候选，不因本次修复自动启用。

本次所有权和组合边界见 [模块关系说明](../docs/WORKBENCH_MODULES.md)。


每块另记录独立课题、状态预算、反例、扩展点与证明义务。部分状态仍依赖未有限化的 DOM、网络或存档条件；这构成待验证义务，不通过一个主观复杂度分数覆盖。源文件注释按这些责任解释原因和作用域。

`npm run models` 为结束接纳及图片效果提供有限分类的可执行检查；范围见 [模型说明](../development/models/README.md)。契约记录字段存在不等于证明完成。
