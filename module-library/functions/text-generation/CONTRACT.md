# F-002 文本请求与协议适配

类型：function。效果目标：`text.request-response`。版本：0.1.0。

## 输入与输出

- 输入：config、messages、settings、tools，可注入 signal 与 fetchImpl。
- 输出：text、toolCalls、rawAssistant、usage、finishReason 或 AppError。

## 条件假设

- 端点、凭据、模型与协议兼容
- 浏览器 CORS、账户权限、额度、模型字段能力须按环境验收

## 待完整证明的保证

- 按协议构造请求和原生工具历史
- 失败不自动重试
- 保留调用返回的协议关联数据

这些是需要验收的契约。局部测试只支持其中的已覆盖情形，不能据此报告全域形式证明。

## 状态、关系和副作用

请求局部状态；通过 src/logs.js 使用进程/页面共享日志与密钥脱敏状态。

调用 fetch；可能产生计费与通讯日志。

源码唯一来源：[src/core.js](../../../src/core.js)。入口仅封装导出边界；core.js 中的职责尚未物理拆开。独立入口不等于独立故障域。依赖闭包、测试与本文件均进入证据指纹。

## 已知限制与不保证的效果

- HTTP 错误体被统一文案替换
- 参数范围为当前实现政策
- 没有真实文本 API 的本次验收

## 最低局部实验

运行 `npm run modules:verify`，执行登记的本地用例和借用入口用例；请求构造、错误、取消、组合历史按相关测试文件验收。网络由合成 fetch 提供，外部 API 可用性不在这份通过结论内。

登记用例：[tests/core.test.js](../../../tests/core.test.js)。
